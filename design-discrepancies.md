# Design discrepancies and adaptations

The Figma page was used read-only. No major unresolved visual discrepancy is known.

## Approved adaptations

- Screen text, item identity, prices, sizes, and totals follow the user’s selections instead of the inconsistent fixed examples across frames. A $125.98 item’s 10% shopping bonus rounds to $12.60; the design example displays $12.59.
- All catalog detail pages and provider expansions reuse their designed templates with sample data, as approved.
- A thank-you screen with confetti and five-second reset was explicitly requested. It reuses existing typography, colors, logo, and success icon.
- Unaffordable paid pickup is disabled with explanatory copy, as requested.

## Minor visual/data limitations

- Long frames scroll within the phone viewport; primary photo/shopping actions remain reachable in the viewport. This makes the 1071–1411 px design frames usable in the 852 px testing viewport.
- Browser cap-height trimming and font rasterization may differ by a few pixels from Figma.
- Color choices update labels and review. Photography stays the supplied image because alternate-color images are not designed for every product.
- Extra size-offer images for the second and third return products reuse that item’s supplied image; the original flow supplies alternate views only for the first jeans item.
- Truncated catalog names are expanded where unambiguous; Pauline’s truncated source label is retained. Product ratings and variant options are sample values from the designed detail template.
- Drop-off maps, addresses, and hours are the supplied UPS sample for every provider, as approved. Delivery dates and the sample address remain the design’s static data.
- The Code Connect status-bar example referenced a component unavailable in this empty project. The implementation uses the original Figma status icons and equivalent time layout.
